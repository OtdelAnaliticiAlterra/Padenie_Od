# Отчёт по падению продаж ОД

Скрипт автоматизирует формирование ежемесячного отчёта по падению продаж
отдела дистрибуции (ОД). Заменяет ручную выгрузку из DBeaver, форматирование
Excel и вставку формул ВПР. Дополнительно умеет скачивать прошлый отчёт
из облака Алтерра и загружать готовый обратно.

## Что делает

1. Считает три периода от текущей даты.
2. **Скачивает прошлый отчёт из облака Алтерра** в `Старый файл/`.
3. Выполняет SQL из `sql/report.sql` и забирает данные из PostgreSQL.
4. Читает прошлый отчёт из папки `Старый файл/`.
5. Делает два «ВПР» в pandas:
   - **#1** — тянет колонки F:M старого отчёта в N:U нового по ключу `Ключ`;
   - **#2** (fallback) — дозаполняет **только пустые** ячейки T и U нового
     отчёта значениями из T и U старого.
6. Открывает Excel-шаблон `Шапка/header_template.xlsx`.
7. Заполняет:
   - строку 6 — подписи периодов (F6, G6, H6);
   - A9:K{последняя} — данные из SQL (без нулей в F:J);
   - N9:U{последняя} — данные из старого отчёта (без нулей и `#Н/Д`);
   - T9:U{последняя} — fallback, только в пустые ячейки.
8. Применяет форматы чисел, автоширину, автофильтр.
9. Сохраняет результат в
   `Новый файл/Анализ падения по видам номенклатуры <ДД.ММ.ГГ>-<ДД.ММ.ГГ>.xlsx`.
10. **Загружает готовый отчёт в облако Алтерра.**
11. **Удаляет** прошлый отчёт из `Старый файл/` (локально).

Логика периодов
Все периоды считаются от текущей даты (date.today()) на момент запуска.
Ручной ввод дат не требуется.

1-й период (текущий): с 26 числа месяца (текущий − 2) по 25 число
текущего месяца.

2-й период (прошлый): 1-й минус 1 год.

3-й период (дополнительный): 2-й плюс 2 месяца.

Пример на 28.09.2026:

Период	Диапазон
Текущий	26.07.2026 – 25.09.2026
Прошлый	26.07.2025 – 25.09.2025
Дополнительный	26.09.2025 – 25.11.2025
Параметры вынесены в config.py:

PERIOD_MONTHS = 2 — длина окна в месяцах;

PERIOD_START_DAY = 26 — начало периода.

Привязки к конкретному году в коде нет — всё считается относительно
date.today(), так что в 2027 году скрипт будет работать так же корректно.

Работа с облаком Алтерра
Используется API https://cloud.tg-alterra.ru/api/v1. Авторизация —
Bearer-токен в заголовке Authorization.

Поиск прошлого отчёта
В папке облака (ID из CLOUD_PREVIOUS_FOLDER_ID) скрипт ищет все файлы,
чьё имя содержит CLOUD_PREVIOUS_FILE_NAME (по умолчанию —
"Анализ падения по видам номенклатуры") и заканчивается на .xlsx.
Из найденных берётся самый свежий по id — то есть последний
загруженный.

Такая логика опирается на то, что:

Скрипт запускается раз в месяц.

В конце каждого запуска он заливает новый файл в ту же папку.

Значит, «последний загруженный» — это результат прошлого запуска,
и он же — «прошлый отчёт» для текущего.

Загрузка готового отчёта
Готовый файл заливается в ту же папку (CLOUD_OUTPUT_FOLDER_ID).
Имя сохраняется (совпадает с локальным). Если запустить скрипт дважды
за один день — в облаке появятся два файла с одинаковым именем.
Если такая ситуация возможна, скажите — добавим проверку и удаление
предыдущего дубля.

Структура Excel-файла
Шапка (строки 1–7)
Статичная, из шаблона. Единственное, что обновляется автоматически:

F6 — подпись «прошлого» периода;

G6 — подпись «текущего» периода;

H6 — подпись «дополнительного» периода.

Заголовки колонок (строка 8)
Тоже из шаблона. Скрипт их не перезаписывает.

Данные (с 9-й строки)
Колонки	Что внутри	Источник
A:K	основной отчёт	SQL (report.sql)
L:M	ручное заполнение	пусто, пользователь заполняет сам
N:U	данные из прошлого отчёта	VLOOKUP #1 + fallback (#2)
Закрепление шапки не применяется — по требованию заказчика.

VLOOKUP: подробнее
#1 (обязательный)
Берём из старого отчёта колонки F:M и по ключу Ключ подставляем
в N:U нового отчёта. Соответствие задано в config.py:

python
LOOKUP_MAP = {
    "Прошлый период":           "Выручка период сравнения",
    "Период":                   "Выручка текущий период",
    "Период дополнительный":    "Выручка третий период",
    "Абсолютный прирост":       "Абсолютный прирост",
    "Относительный прирост, %": "Относительный прирост",
    "Падение":                  "Падение",
    "Мероприятия":              "Мероприятия",
    "Результат":                "Результат",
}
⚠️ Важно: значения (справа) — это реальные имена колонок в старом
файле. Если в старом отчёте появились суффиксы .1 (pandas так
разрешает дубликаты имён), это надо учесть. Список реальных колонок
виден в тексте ошибки KeyError, если маппинг не сходится.

Если в старом отчёте колонки называются иначе — правим только
этот словарь, код трогать не нужно.

#2 (fallback)
Иногда в старом отчёте колонки L:M (Мероприятия / Результат) пустые,
но в его же блоке N:U (колонки T:U старого) есть значения — они были
заполнены ещё раньше. Fallback подтягивает их в те ячейки T:U нового,
которые остались пустыми после #1.

Задаётся в config.py:

python
LOOKUP_FALLBACK_BY_INDEX = {
    "Мероприятия": 19,   # T старого (0-based)
    "Результат":   20,   # U старого (0-based)
}
Здесь маппинг по позиции, а не по имени — потому что в старом
файле две пары колонок с одинаковыми именами (L:M и T:U).

Обработка «нулей» и ошибок
Колонки F:J и N:R — если значение ровно 0, ячейка остаётся пустой
(нужно, чтобы 1230 не превращалось в 123 при форматировании).

#Н/Д, #N/A, пустые строки — тоже превращаются в пустые ячейки.

NaN из pandas — тоже пусто.

Настройки в config.py
Параметр	Назначение
PERIOD_MONTHS	длина окна (2 месяца)
PERIOD_START_DAY	начало периода (26)

CLOUD_PREVIOUS_FOLDER_ID	ID папки облака для скачивания прошлого отчёта
CLOUD_OUTPUT_FOLDER_ID	ID папки облака для загрузки готового отчёта

Частые проблемы
В облаке (папка ID=...) не найдено файлов по подстроке '...' —
в указанной папке нет ни одного .xlsx, имя которого содержит
CLOUD_PREVIOUS_FILE_NAME. Проверь ID папки и подстроку в config.py.

401 Unauthorized — неверный или просроченный CLOUD_API_TOKEN.

403 Forbidden — у токена нет прав files:read / files:write,
или нет доступа к самой папке.

FileNotFoundError: .../Шапка/header_template.xlsx — нет шаблона
по указанному пути. Проверь config.TEMPLATE_FILE и наличие файла.

В старом отчёте не найдены колонки: [...] — изменились названия
колонок в старом файле. Открой старый файл, посмотри реальные заголовки
и поправь LOOKUP_MAP в config.py.

Не заданы переменные окружения — не заполнен .env или не все
ключи в нём есть.

Ошибка с кодировкой кириллицы в консоли Windows — добавь в начало
main.py:

python
import sys
sys.stdout.reconfigure(encoding="utf-8")
Как добавить новый отчёт
Ничего вручную делать не нужно — просто запусти:

bash
python main.py
Скрипт сам:

Найдёт в облаке самый свежий отчёт (он же — «прошлый»).

Скачает его в Старый файл/.

Сформирует новый отчёт в Новый файл/.

Загрузит его в облако.

Удалит локальный файл из Старый файл/.
